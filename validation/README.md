# Validation against MIRtoolbox 1.8.2

The parity tests compare py-mir-toolbox outputs with reference outputs from MIRtoolbox 1.8.2. The reference outputs come from [pymirtoolbox](https://github.com/frshdjfry/pymirtoolbox), which wraps a compiled MIRtoolbox 1.8.2 and runs it on the free MATLAB Runtime R2025b (Linux; Python 3.10–3.12). No MATLAB licence is needed.

The fixtures will be stored in a separate repository (`py-mir-toolbox-test-data`) with a Zenodo DOI. They are generated by the `fixtures` GitHub Actions workflow, which is started by hand.

## Tolerances

| Stage | Tolerance |
|---|---|
| Framing, FFT spectrum, autocorrelation, RMS | `rtol=1e-6` |
| Filter-based (filterbank, envelope) | `rtol=1e-4` |
| Discrete outputs (key, tempo, peak positions) | exact, or within one bin |
| NaN values | must match (`equal_nan=True`) |

pymirtoolbox does not yet wrap every MIRtoolbox function. Fixtures for the remaining functions will be generated by a collaborator with MATLAB.

## Running the parity tests

Parity tests live in `tests/parity/` and are skipped when their fixture is missing, so the normal test suite runs without fixtures. To run them:

```sh
MIRPY_FIXTURES=/path/to/fixtures uv run --group test pytest tests/parity
```

Each comparison is recorded in `build/parity_results.json` (override with `MIRPY_PARITY_REPORT`): max absolute and relative error, Pearson r, the share of values within tolerance, and whether NaNs match. This file feeds the Parity report page of the docs.

A parity test uses the `mirtoolbox_fixture` and `assert_parity` pytest fixtures, and converts MIRtoolbox's `(element, frame, channel)` arrays with `from_matlab_axes`:

```python
from parity.harness import Stage, from_matlab_axes


def test_rms_frame(mirtoolbox_fixture, assert_parity):
    ref = mirtoolbox_fixture("ragtime", "rms_frame")
    x = mirpy.rms(mirpy.Audio.from_file("ragtime.wav"), frame=True)
    assert_parity(x.data, from_matlab_axes(ref.arrays["data"]), Stage.LINEAR, "rms_frame")
```
